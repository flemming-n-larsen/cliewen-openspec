# First-use walkthrough

Use `reference/docs/guide/getting-started.md` as a developer who has not used Cliewen before. Actually execute the walkthrough in this workspace, through archive and refreshed evidence. Read other supplied public guide pages when needed. The guide reflects the website: include directives have been expanded for you.

Use the development package built from the source checkout as directed. The published 0.1 package is a different artifact. You may clone the public repository named by the guide and download npm dependencies. Do not read its maintainer plans, decisions, previous trial results, or in-flight change proposals. Prefer the public guide over source inspection; if you inspect code to recover from an unclear instruction, record why.

Work only inside this workspace. Keep temporary probes and logs here. Do not inspect sibling evaluator artifacts, other projects, credentials, or old conversations. Do not spawn agents, contact people, push, publish a package, or open a PR. Model-provider requests, cloning the documented public source, and package installation are allowed. Read the workspace AGENTS.md explicitly. Set Git identity locally in the pilot if necessary; do not change global configuration. Commits and archive are authorized only in the disposable walkthrough repositories.

Do not fix the source guide or package. If a step is unclear, record what you expected, the command you tried, the observed outcome, and your smallest workaround. Stop on a genuine blocker instead of inventing success. Distinguish missing prerequisites, confusing documentation, tool failures, and product defects.

We will ask afterward what was missing and request a review of the guide. For now, complete the walkthrough and preserve observations; defer that retrospective review until the follow-up question.

At the end, write `walkthrough-result.md` in the workspace root with status complete or blocked, source revision and package version, actual final checks, warnings, workarounds, remaining obstacles, and any inherited instructions you could observe. State the pilot path and final tested Git revision. Keep this report outside the pilot so it does not invalidate its evidence. Then give a brief final status.
